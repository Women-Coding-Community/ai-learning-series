# Badge Criteria & Participation Tracking

## Overview

Participants earn badges by completing sessions and projects. Badges are tracked on GitHub and displayed in your profile.

## Badge System

### 🏆 Participation Badges

#### **Harness Series Badge (2026)**

🛠️ **Harness Complete** - All 6 sessions + a working harness you keep

**Earn by completing:**

- ✅ All 6 Harness Series sessions (live or recording): Agent Skill, Tools & Boundaries, Small Models, Sub-Agents, SDLC & CI/CD, Loop Engineering
- ✅ Submit working artifacts to GitHub for at least 3 sessions (e.g. `AGENTS.md`/`SKILL.md`, MCP + hook config, a model endpoint, a sub-agent split, a CI check, a scheduled loop)
- ✅ By the end of Session 6, have one end-to-end harness: a skill, scoped tools, a model, and at least one automated check or loop, all working together
- ✅ Write a README for your harness with:
  - What you built
  - How to run it
  - What you learned
  - Challenges faced
  - Future improvements
- ✅ Review at least 1 peer submission (provide constructive feedback)

**Submit to:** `sessions/session-0X-.../participants/[your-username]/`

## Submission Process

### Step 1: Create Your Folder

```bash
mkdir -p sessions/session-01-agent-skill/participants/[your-username]
cd sessions/session-01-agent-skill/participants/[your-username]
```

### Step 2: Add Your Files

```bash
[your-username]/
├── code/
│   ├── chatbot.py
│   ├── requirements.txt
│   └── ...
├── README.md
└── demo.mp4 (optional)
```

### Step 3: Write README

Include:

- What your project does
- How to set it up
- How to run it
- What you learned
- Challenges faced
- Future improvements

### Step 4: Submit PR

1. Commit your changes
2. Push to your fork
3. Create a Pull Request
4. Link to your submission in the PR description

### Step 5: Verification

- Instructors review your submission
- Provide feedback
- Approve and merge when complete
- Badge is awarded!

---

## Submission Requirements

### README Must Include

- **What you built:** Clear description of your project
- **How to run it:** Step-by-step setup and execution instructions
- **What you learned:** Key takeaways from the session
- **Challenges faced:** Problems encountered and how you solved them
- **Future improvements:** Ideas for enhancing the project

### Code Quality Standards

- ✅ Code is clean and well-organized
- ✅ Proper error handling implemented
- ✅ Good inline documentation/comments
- ✅ Follows Python best practices
- ✅ Requirements.txt with all dependencies

### Peer Review Expectations

When reviewing peer submissions:

- ✅ Provide constructive feedback (at least 2-3 comments)
- ✅ Highlight what they did well
- ✅ Suggest improvements or enhancements
- ✅ Ask clarifying questions
- ✅ Be respectful and encouraging

## FAQ

**Q: Can I submit late?**  
A: Yes! Submit anytime. Late submissions are still eligible for badges.

**Q: What if my code doesn't work perfectly?**  
A: That's okay! We value effort and learning. Document issues and what you tried.

**Q: Can I use different platforms (AWS, Azure)?**  
A: Absolutely! Adapt the requirements to your platform.

**Q: Do I need to attend live sessions?**  
A: Not required, but recommended. Recordings are available.

**Q: Can I work with others?**  
A: Yes! Collaboration is encouraged. Just document who you worked with.

**Q: How long do badges stay valid?**  
A: Forever! They're part of your learning journey.
